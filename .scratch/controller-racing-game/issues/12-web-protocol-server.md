# 12: Web protocol + server

**What to build:** A web server thread runs beside the sim loop and streams two message kinds over WebSocket: on connect, one static message (centerline, occupancy grid as origin/resolution/occupied cells, track width, start line); then a dynamic snapshot every ~150 ms (sim time, phase, countdown, per-vehicle id/name/position/heading/speed/steering/lap/status/best lap/last lap/crash count/finish time). `null` in JSON stands for a no-hit beam. The protocol serializer is a pure function (state → JSON) and is tested for the static and dynamic message shapes — no server or socket tests. Phase and countdown come from the engine; the static message reads `Track` fields directly. CLI wiring: the web view is on by default, and the headless flag disables it with the race running identically either way. A minimal static page is served so a live race is watchable in the browser (basic track outline + car dots + status text; the full renderer lands in 13).

## Comments

- 2026-08-27: Done. New package `cocoracer/web/`: `protocol.py` holds the two pure serializers — `build_static_message(track)` (centerline, occupancy grid as origin/resolution/occupied cell pairs, track width, start line) and `build_dynamic_message(snapshot, phase, countdown, scans)` (sim time, phase, countdown, per-vehicle id/name/x/y/yaw/speed/steering/laps/status/best_lap/last_lap/crashes/finish_time/scan); `null` covers no-hit beams (`np.inf`) and not-yet-existing laps, times, and scans, and `status` is `VehicleStatus.value` so all five statuses serialize. `server.py` builds the FastAPI app (GET / serves `index.html`; WS /ws sends the static message on connect, then a dynamic message every 150 ms reading `engine.snapshot()`, `engine.phase`, `engine.countdown`, `engine.last_scans`) and a `WebServer` wrapper that runs uvicorn in a daemon thread with a bounded start wait (SystemExit on a busy port) and an explicit `stop()`; the web thread never paces the sim. `index.html` is the minimal watchable page (centerline band, start line, one dot per vehicle colored by status, HUD line). Engine accessors added in `engine.py`: `phase`, `countdown`, `last_scans` (cached in `_step_controllers`, one per vehicle, `None` until first step) and `results`; `run()` is now the same `while not finished: tick()` loop the CLI live path uses, so both stop conditions are one code path. CLI: the web view is on by default — `_run_live` starts the server, prints the URL, then paces `engine.tick()` against the wall clock at `config.sim.tick_dt` (verified exactly 25 ms/tick, 12.70 s wall for 12.70 s sim); `--no-web` runs the unchanged headless `run_race`. Smoke-verified over a real WebSocket: static message on connect, countdown→racing phase with the countdown field draining, cars moving, crash→ghost transition, scans with `null`s, clean process exit. Deviations: the venv had no WebSocket implementation (uvicorn's upgrade returned 404), so `websockets>=12.0` was installed and added to `pyproject.toml`; `test_time_trial_without_no_web_prints_headless_note` is replaced by a live test (short `time_limit` temp params, a free port, asserts the URL is printed, the old note is gone, and the race still reports) since the issue removes that print; the live path imports `WebServer` lazily inside `_run_live` so `--no-web` stays free of the fastapi/uvicorn import.
